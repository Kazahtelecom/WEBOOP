# Стенд замера цены Pyodide

Измеряет цену запуска Python в браузере для релиза `pyodide-core` **314.0.7** и **отдельно** —
в двух режимах отдачи, потому что объём по сети почти целиком определяется сжатием на сервере.
Продуктовой ценности стенд не несёт: он классифицирован как `ASSURANCE`, а не `VALUE`.

> **Исправление.** Первая версия этого README утверждала, что документация Pyodide ошибочно
> называет ассет `.tar.gz`. **Это утверждение снято:** достижимая страница 314.0.7, её `_sources`
> и страница 0.19.1 говорят `.tar.bz2`. Ошибка была в первой версии стенда, а не в документации.
> Также снято утверждение, что «сжатие почти ничего не даёт»: первый замер шёл через
> `python -m http.server`, который **не отправляет `Content-Encoding`**, поэтому и объём был
> несжатым. Обе ошибки найдены независимым review (находки F1 и F5).

## Что измеряется

| Метрика | Как получается | Почему важна |
|---|---|---|
| Объём раздачи | Сумма распакованных файлов архива `pyodide-core-314.0.7.tar.bz2` | Оценка объёма, который нужно раздавать |
| Байты по сети | Chrome DevTools Protocol, домен `Network`, поле `encodedDataLength` | Честный объём с учётом того, что реально сделал сервер |
| Время до готовности рантайма | `performance.now()` вокруг `import()` + `loadPyodide()` | То, что почувствует студент. **Включает** инициализацию интерпретатора, поэтому не складывается с ней |

## Три факта, без которых число не является измерением

Записывать обязательно, иначе результат нельзя сравнивать:

1. **Браузер и версия** — замеры в разных браузерах не сравнимы.
2. **Состояние кеша** — первая загрузка и повторная дают разные числа; продуктовой задаче нужна первая.
3. **Состояние сжатия на сервере** — `encodedDataLength` сообщает то, что сервер действительно
   отправил. Если сервер не ставит `Content-Encoding`, число будет несжатым, и сравнивать его со
   сжатой цифрой из документации нельзя. Именно на этом первая версия стенда и ошиблась.

## Результат на 2026-10-08 (Chrome 154.0.8037.98, чистый профиль на каждый прогон)

| Отдача | Байты по сети | Время до готовности |
|---|---|---|
| Без сжатия (`python -m http.server`, порт 8801) | 12.92 MiB (13 542 894 Б) | 1.84 с |
| Со сжатием gzip (`serve_compressed.py`, порт 8802) | **6.10 MiB (6 391 410 Б)** | 2.18–2.34 с |

Декодированная нагрузка в обоих случаях 12.91 MiB, то есть gzip сжимает примерно в 2.12 раза.
Число `6.4 MB` из roadmap Pyodide **подтвердилось**: это сжатая загрузка, и расхождение с замером
составляет 4.5 %.

## Как воспроизвести

### Шаг 1. Скачать раздачу локально

```
python fetch_core.py
```

Скрипт использует только стандартную библиотеку Python (`urllib`, `tarfile`) и кладёт файлы в
`vendor/pyodide-core/`. Версия закреплена в скрипте и в этом README.

### Шаг 2. Раздать статически

```
python -m http.server 8801 --directory .
```

Сервер разработчика не требуется: достаточно статической раздачи
([документация Pyodide](https://pyodide.org/en/stable/usage/downloading-and-deploying.html)).

### Шаг 3. Поднять раздачу в обоих режимах

```
python -m http.server 8801 --bind 127.0.0.1      # без сжатия
python serve_compressed.py 8802                  # с gzip
```

`serve_compressed.py` сжимает `.wasm`, `.mjs`, `.js`, `.html`, `.json`, `.py` на лету и пишет в
stderr, что именно он сделал с каждым файлом. Оба сервера нужны потому, что число по сети
почти целиком определяется сжатием: сравнивать замер несжатой отдачи со сжатой цифрой из
документации нельзя.

### Шаг 4. Замерить

```
node measure.mjs --port 8801 --runs 2 --label uncompressed
node measure.mjs --port 8802 --runs 2 --label compressed
```

`measure.mjs` запускает уже установленный Chrome или Edge в headless-режиме, подключается к нему
по Chrome DevTools Protocol через встроенный в Node клиент `WebSocket` (**внешних зависимостей нет**)
и печатает отчёт. Флаг `--label` задаёт имя файла отчёта, чтобы режимы не перезаписывали друг друга.

Опции:

```
node measure.mjs --port 8801 --url http://127.0.0.1:8801/index.html --browser auto --runs 2
node measure.mjs --browser "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

## Честные ограничения стенда

- **Состояние сжатия зависит от сервера, а не от рантайма.** Стенд не ставит `Content-Encoding`
  сам; это делают `http.server` (никак) и `serve_compressed.py` (gzip). Число без указания режима
  бессмысленно.
- **Кеш.** Каждый прогон получает отдельный временный профиль, поэтому все прогоны — первичные;
  это указано в отчёте путём профиля.
- **Сеть.** Объём зависит от сети между машиной и сервером; здесь сервер локальный, поэтому
  транспортные потери минимальны и число близко к нижней границе.
- **Время до готовности включает инициализацию интерпретатора.** Оно измеряется вокруг
  `import()` плюс `loadPyodide()` и не складывается с отдельным «временем инициализации».
- **`runs: 2` по умолчанию** — первое число и повтор дают разброс; отчёт печатает оба.
