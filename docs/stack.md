# Технологический стек и архитектурные решения (ADR-001)

Документ фиксирует выбор технологического стека для мини-LMS **WEBOOP**.

## 1. Контекст и цели выбора

Главные критерии выбора стека:
1. **Дружественность к ИИ-агентам (AI-Friendliness):** стек должен быть массовым, стандартизированным, строго типизированным и предсказуемым для любой LLM (Claude, GPT, Gemini), чтобы любой агент мог быстро ориентироваться в кодовой базе, писать чистый код без галлюцинаций и автоматически отлавливать ошибки компиляцией.
2. **Прозрачность для человека:** понятная модульная структура, исчерпывающая документация в `docs/`, визуализация через UML/Mermaid.
3. **Local-first и автономность:** работа строго в браузере без внешних бэкендов, баз данных и деплоя.
4. **Безопасность выполнения кода:** песочница для Python без риска зависания UI интерфейса.

## 2. Матрица технологий

| Слой | Выбранная технология | Альтернативы (отклонено) | Причина выбора для ИИ и проекта |
|---|---|---|---|
| **Язык** | **TypeScript (strict)** | Чистый JavaScript, Python GUI | Строгая система типов исключает класс ошибок с неверными форматами данных, автодополнение и линтинг помогают ИИ не делать ошибок в API контрактах. |
| **Сборщик / Dev Server** | **Vite** | Webpack, Parcel, Create-React-App | Минималистичный конфиг (`vite.config.ts`), мгновенный HMR, быстрая сборка статики без сложных плагинов. |
| **UI Фреймворк** | **React 18/19 (Functional + Hooks)** | Vanilla TS, Svelte, Vue | Самая обширная обучающая база у всех существующих LLM. ИИ пишет компоненты на React с максимальной точностью и без выдумывания нестандартных конструкций. |
| **Стилизация** | **Tailwind CSS** | Чистый CSS, CSS-Modules, Styled Components | Локальность стилей прямо в разметке компонента. ИИ не нужно прыгать по разным файлам стилей или галлюцинировать с глобальными именами классов. |
| **Python Runtime** | **Pyodide в Web Worker** | Запуск Pyodide в Main Thread, бэкенд на FastAPI/Flask | Pyodide в Web Worker изолирует выполнение пользовательского кода. Любой бесконечный цикл (`while True:`) от студента не вешает страницу и может быть безопасно прерван (terminate). |
| **Редактор кода** | **CodeMirror 6** (или Monaco Editor) | Простой `<textarea>` | Полноценная подсветка синтаксиса Python, номера строк и легкий вес по сравнению с тяжелым Monaco. |
| **Состояние и хранение** | **Zustand + localStorage** | Redux, MobX, IndexedDB | Простой, декларативный, типизированный стор в 1 файл. Прогресс студента и баллы сохраняются в браузере без сложной инфраструктуры. |

## 3. Критический анализ (Адвокат дьявола)

Перед фиксацией выбора были проанализированы потенциальные риски:

1. **Риск: React может быть избыточен для 3-недельного курса.**
   * *Контраргумент:* LMS требует интерактивного сплит-экрана (теория слева, редактор кода и терминал вывода справа, переключение вкладок, реактивный счётчик баллов). Делать это на чистом DOM выльется в сотни строк самописного императивного кода, в котором ИИ-агентам легче запутаться, чем в стандартных декларативных компонентах React.
2. **Риск: Длинные классы Tailwind расходуют токены контекста.**
   * *Контраргумент:* Экономия токенов на отсутствии необходимости загружать отдельные CSS-файлы и селекторы полностью нивелирует этот фактор. Компонент остаётся самодостаточным.
3. **Риск: Сложность асинхронного обмена с Web Worker.**
   * *Решение:* Строго типизированный протокол сообщений `WorkerMessage` (см. `architecture.md`), где каждый запрос и ответ типизированы через TypeScript Discriminated Unions.

## 4. Соглашения по разработке для ИИ-агентов

Любой агент, вносящий изменения в проект, обязан соблюдать правила:
1. **Строгая типизация:** Никаких `any`. Все структуры данных уроков, тестов и состояния строго описаны в `src/types/`.
2. **Чистые функции и изоляция:** Бизнес-логика проверки тестов отделена от UI-компонентов.
3. **Документирование изменений:** Любое изменение архитектуры или модели данных сопровождается обновлением соответствующих файлов в `docs/`.
