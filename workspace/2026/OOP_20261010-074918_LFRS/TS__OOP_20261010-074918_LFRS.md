## 1. Objective

Сформировать и верифицировать рабочий программный фундамент клиентской мини-LMS **WEBOOP**:
1. Развернуть и настроить проект на React 18/19 + TypeScript (strict) + Vite + Tailwind CSS.
2. Реализовать строгие доменные интерфейсы из [`docs/domain/model.md`](../../docs/domain/model.md) в `src/types/course.ts` без использования типа `any`.
3. Создать изолированный Web Worker с рантаймом Python (`pyodide` WASM CPython 3.14), перехватом `stdout/stderr` и защитным сторожевым таймером на 5 секунд.
4. Разработать реактивный стор состояния на Zustand с мгновенной синхронизацией в `localStorage` и поддержкой экспорта/импорта в JSON.
5. Собрать двухпанельный интерфейс (SplitPane): левая панель с теорией (Markdown), правая панель с редактором кода CodeMirror 6 (подсветка Python) и консолью терминала/результатов тестов, сайдбар навигации по курсу.
6. Включить минимальный демонстрационный модуль (1 лекция-заглушка и 1 задача с assert-тестами на класс `Counter`) для сквозной проверки без контента Недели 1.

## 5. Acceptance Criteria

### AC-1: Инфраструктура сборки и тулинг
- [ ] В корне репозитория созданы файлы `package.json`, `tsconfig.json`, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`, `index.html`.
- [ ] Установлены зависимости: `react`, `react-dom`, `@types/react`, `@types/react-dom`, `vite`, `typescript`, `tailwindcss`, `postcss`, `autoprefixer`, `zustand`, `@uiw/react-codemirror`, `@codemirror/lang-python`, `vitest`.
- [ ] Команды `npm run build` и `npm run typecheck` выполняются успешно (код возврата 0).

**Gate:** `npm run typecheck && npm run build`  
**Evidence:** Вывод команд компиляции и сборки бандла в `dist/`.

---

### AC-2: Доменные типы и протокол сообщений
- [ ] Файл `src/types/course.ts` содержит точные интерфейсы из [`docs/domain/model.md`](../../docs/domain/model.md): `Course`, `WeekModule`, `Lesson`, `InteractiveCheck`, `CodeTask`, `ExamModule`, `StudentProgressState`.
- [ ] Файл `src/types/worker.ts` содержит строго типизированный протокол `WorkerMessage` (дискриминированные объединения для типов запросов: `'INIT'`, `'RUN_CODE'`, `'RUN_TESTS'`, и ответов: `'READY'`, `'RUN_SUCCESS'`, `'TEST_RESULTS'`, `'ERROR'`).
- [ ] Ни в одном типе не используется `any`.

**Gate:** `npm run typecheck`  
**Evidence:** Отсутствие диагностических ошибок TypeScript strict.

---

### AC-3: Web Worker с Pyodide и сторожевым таймером
- [ ] Создан Web Worker `src/workers/pyodide.worker.ts`, который инициализирует Pyodide (WASM).
- [ ] Воркер принимает код на Python, исполняет его в виртуальном CPython 3.14 и перехватывает `sys.stdout` и `sys.stderr`.
- [ ] Воркер принимает тестовый код (`testCode`) и запускает проверки утверждений (assertions).
- [ ] В главном потоке реализован таймаут 5 секунд: при зацикливании (`while True:`) воркер прерывается через `terminate()`, не блокируя вкладку браузера, возвращает ошибку таймаута и создается новый экземпляр воркера.

**Gate:** Unit-тест или смоук-скрипт запуска кода и проверка прерывания бесконечного цикла.  
**Evidence:** Зафиксированный в EV вывод успешного исполнения скрипта `print("Hello from Pyodide")` и перехвата бесконечного цикла через watchdog.

---

### AC-4: Состояние Zustand и персистентность LocalStorage
- [ ] Создан стор `src/store/useCourseStore.ts` на Zustand с плагином `persist` в `localStorage`.
- [ ] В сторе хранятся: `activeStepId`, `userSavedCode: Record<string, string>`, `completedTasks: Record<string, boolean>`, `currentScore: number`.
- [ ] Изменение кода в редакторе автоматически сохраняется в `localStorage` без задержек.
- [ ] При обновлении страницы (`F5`) набранный код для текущей задачи и начисленные баллы восстанавливаются из `localStorage`.
- [ ] Реализованы методы `exportProgress()` (скачивание JSON) и `importProgress(jsonString)` (восстановление состояния из файла).

**Gate:** `npm test tests/store.test.ts`  
**Evidence:** Unit-тесты стора и проверка сохранения в `localStorage`.

### AC-6: Сквозная интеграция демо-задачи (End-to-End Smoke Test)
- [ ] Создан файл `src/data/demoCourse.ts` с одной тестовой практической задачей ("Создайте класс Counter с методами inc() и get_value()").
- [ ] В интерфейсе при нажатии кнопки «Запустить код»:
  1. Код передается в воркер.
  2. Pyodide выполняет код и прогоняет проверочные тесты.
  3. В терминале отображается `[OK] Все тесты пройдены`.
  4. В шапке студенту начисляются демо-баллы (+10 баллов).
  5. В `localStorage` фиксируется выполнение задачи.
- [ ] Материалы Недели 1 в кодовую базу не включены.

**Gate:** Сквозной тест выполнения задачи и верификация в браузере.  
**Evidence:** Запись в `evidence/EV__OOP_20261010-074918_LFRS.md` со статусом `VERIFIED`.

## 6. Technical Guidance

- Инициализацию проекта рекомендуется выполнить с помощью `npm create vite@latest . -- --template react-ts` с сохранением существующих файлов `.tfw/`, `docs/`, `workspace/`, `team/`.
- Для интеграции CodeMirror 6 использовать официальные пакеты `@uiw/react-codemirror` и `@codemirror/lang-python`.
- Для загрузки Pyodide в Web Worker использовать динамический импорт или `importScripts` из официального CDN: `https://cdn.jsdelivr.net/pyodide/v0.26.4/full/pyodide.js` (это исключит раздувание бандла Vite тяжелыми WASM-бинарниками и гарантирует соответствие `KR-OOP-0001`).
- При перезапуске воркера после таймаута использовать фабричную функцию `createPyodideWorker()`.

## 7. Definition of Failure

- ❌ 1. Наличие внешних серверов (FastAPI, Express) или баз данных.
- ❌ 2. Выполнение кода Pyodide в главном потоке React.
- ❌ 3. Зависание UI при вводе `while True:`.
- ❌ 4. Потеря набранного кода при перезагрузке страницы.
- ❌ 5. Использование типа `any` в кодовой базе.
- ❌ 6. Ошибки при выполнении `npm run build` или `npm run typecheck`.
