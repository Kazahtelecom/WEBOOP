## Dimensions

Ключевое различение, вытекающее из ответов владельца: P0 запрещает **деплой и облако**, но не
запрещает исполнение кода в браузере студента. Поэтому измерение «где исполняется код» остаётся
главным, а не «нужен ли интернет».

| Dimension | Alt A | Alt B | Alt C | Alt D |
|-----------|-------|-------|-------|-------|
| D1: Где исполняется код студента | В браузере студента (WebAssembly) | На компьютере студента вне браузера (Node.js/Python) | На внешнем сервисе-песочнице по API | Нигде — код не исполняется |

## Findings

### G1: Pyodide — реальная цена загрузки и исполнения (первоисточник)

Официальный roadmap Pyodide фиксирует конкретные числа: **первая загрузка требует 6.4 MB
скачивания, инициализация окружения занимает 4–5 секунд**; последующие загрузки быстрее, потому
что ресурсы кешируются браузером. Скорость исполнения Python в Pyodide — **примерно в 3–5 раз
медленнее нативного Python**; сам проект называет это направлением для улучшения, то есть цифра
характеризует текущее состояние, а не худший случай.
Источник: [Pyodide Roadmap](https://pyodide.org/en/stable/project/roadmap.html).

### G2: Полная и минимальная раздача Pyodide различаются на порядок

Документация по развёртыванию различает два архива: полная раздача со всеми вендорными пакетами —
**200+ мегабайт**, а `pyodide-core` — «минимальный набор файлов, нужный для запуска Pyodide»,
предназначенный для Node и устанавливаемый через `npm install pyodide`; недостающие пакеты
подтягиваются с CDN. Ядро включает `pyodide.asm.wasm`, `python_stdlib.zip` и
`pyodide-lock.json`. Раздавать файлы можно локально (`python -m http.server`) — то есть **сервер
разработчика не обязателен, достаточно статической раздачи**.
Источник: [Downloading and deploying Pyodide](https://pyodide.org/en/stable/usage/downloading-and-deploying.html).

### G3: Ограничения окружения Pyodide, существенные для учебного кода

Roadmap прямо называет отсутствие сокетов: пакеты вроде `requests`, делающие синхронные сетевые
запросы, работать не могут, и это отдельный пункт дорожной карты, а не решённая задача. Для курса
по ООП это скорее плюс, чем минус — вводный курс по классам и наследованию сети не требует.
Источник: [Pyodide Roadmap](https://pyodide.org/en/stable/project/roadmap.html).

### G4: WebContainers как альтернатива ориентированы на Node.js

StackBlitz WebContainers — среда исполнения в браузере, документированная вокруг Node.js:
описание доступных окружений перечисляет Node-ориентированные среды. Это делает их **менее
естественным выбором для Python-курса**, чем WebAssembly-CPython, и требует дополнительной
проверки на стадии Extract.
Источник: [StackBlitz docs — Available environments](https://raw.githubusercontent.com/stackblitz/docs/cd4e046124595433dfbcf214949a574908df203f/docs/guides/user-guide/available-environments.md).

### G5: Статическая оценка кода в учебном процессе — существующая практика

Обнаружено академическое исследование платформы для практики программирования, построенной на
**статической оценке** (static-assessment), с оценкой в реальной аудитории. Это подтверждает, что
проверка без исполнения кода — не самодельная экзотика, а применяемый подход.
Источник: [Development and Classroom Evaluation of a Static-Assessment Programming Practice Platform](https://ieeexplore.ieee.org/abstract/document/11488980) (IEEE).

### G6: Внешние сервисы проверки кода требуют собственной инфраструктуры

Judge0 позиционируется как сервис исполнения кода; существуют клиентские обёртки для его
самостоятельного развёртывания. Это означает: вариант «внешний сервис» для локального проекта
превращается в **обязанность развернуть и сопровождать чужой сервер**, что прямо конфликтует с P0.
Источники: [Judge0](https://judge0.com/blog/leo-your-24-7-mock-coding-interviewer),
[@javaguru/server-judge0](https://www.npmjs.com/package/@javaguru/server-judge0).
